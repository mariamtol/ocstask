# ระบบมอบหมายและติดตามงาน (Task Management System)

เว็บแอปพลิเคชันสำหรับหัวหน้าหน่วยงานใช้มอบหมายงาน ติดตามความคืบหน้า และรับรายงานปัญหา/อุปสรรคจากพนักงาน

- **Backend:** Python 3 + Flask, SQLite (ไม่ต้องติดตั้งฐานข้อมูลเพิ่ม)
- **Frontend:** Jinja2 templates + Bootstrap 5 + Bootstrap Icons, ฟอนต์ Sarabun (รองรับมือถือ)

## วิธีติดตั้งและรัน

```bash
pip install -r requirements.txt
python run.py
```

เปิด http://localhost:5000 — ครั้งแรกระบบจะสร้างฐานข้อมูลพร้อมข้อมูลตัวอย่างให้อัตโนมัติ
หากต้องการล้างข้อมูลและสร้างข้อมูลตัวอย่างใหม่ ให้รัน `python seed.py` (ข้อมูลเดิมจะถูกลบทั้งหมด)

| `manager` | หัวหน้าหน่วยงาน | `password123` |

> **อัปเกรดจากเวอร์ชันก่อนหน้า:** เมื่อรันแอป ระบบจะปรับโครงสร้างฐานข้อมูลเดิมให้อัตโนมัติโดยข้อมูลไม่หาย

```
  services.py           business logic: คำนวณความคืบหน้า, ตรวจสิทธิ์ตามบทบาท, query, การแจ้งเตือน
  auth.py               เข้าสู่ระบบ / ออกจากระบบ / decorator ตรวจสิทธิ์

  views_reports.py      รายงานผล, ไฟล์แนบ, ความคิดเห็น, สถานะปัญหา
  views_misc.py         การแจ้งเตือน, จัดการผู้ใช้ (admin)
  views_admin.py        ภาพรวมระบบ, บทบาทและสิทธิ์, หน่วยงานและแผนก, ปีการศึกษา, ตั้งค่าระบบ, บำรุงรักษา (admin)
  templates/  static/
instance/               ไฟล์ฐานข้อมูลและ secret key (สร้างอัตโนมัติ)
uploads/                ไฟล์แนบ (เก็บด้วยชื่อสุ่ม แสดงชื่อเดิมตอนดาวน์โหลด)
```

## การออกแบบฐานข้อมูล (ER)

```
departments ──< divisions
departments ──< users.department_id      divisions ──< users.division_id
academic_years ──< tasks.academic_year_id
users ─┬──< task_assignees >──┬─ tasks ──< subtasks >── users (assignee)
       │   (Many-to-Many)     │
       ├──< tasks.created_by ─┘
       │                      tasks ──< reports ──< report_attachments
       ├──< reports.user_id             └────────< report_comments >── users
       └──< notifications
```

| ตาราง | คอลัมน์สำคัญ |
|---|---|
| `users` | username, password_hash, full_name, position, role (→ `roles.code`), is_active, department_id (หน่วยงาน), division_id (แผนก) |
| `roles` | code (unique), name, description, scope (`all`/`division`/`own`), is_system — บทบาท |
| `role_permissions` | (role_id, permission) — สิทธิ์ของแต่ละบทบาท |
| `departments` | name (unique) — หน่วยงาน |
| `divisions` | department_id, name (unique ภายในหน่วยงาน) — แผนก |
| `academic_years` | year_be (ปี พ.ศ., unique), start_date, end_date, is_current |
| `settings` | key, value (ชื่อหน่วยงาน, จำนวนวันแจ้งเตือนล่วงหน้า) |
| `tasks` | title, description, start_date, due_date, priority (`low`/`medium`/`high`/`urgent`), status (`not_started`/`in_progress`/`done`/`on_hold`), manual_progress, academic_year_id, created_by |
| `task_assignees` | (task_id, user_id) — ความสัมพันธ์ Many-to-Many |
| `subtasks` | task_id, title, assignee_id, due_date, weight (% ของงานหลัก, รวมทุกงานย่อยไม่เกิน 100), progress (0–100), status |
| `reports` | task_id, user_id, report_date, result, problems, obstacles, help_needed, issue_status (`none`/`open`/`resolved`) |
| `report_attachments` | report_id, original_name, stored_name, size_bytes |
| `report_comments` | report_id, user_id, body |
| `notifications` | user_id, type, message, link, is_read, dedupe_key (กันแจ้งเตือนซ้ำ) |

## สิทธิ์การใช้งาน

สิทธิ์ทั้งหมด **ปรับได้ที่เมนู ผู้ดูแลระบบ → จัดการบทบาทและสิทธิ์** (`/admin/roles`) ซึ่งเป็นตาราง บทบาท × สิทธิ์:

- **ขอบเขต (scope)** ของแต่ละบทบาท: `ทั้งหน่วยงาน` (เห็นทุกงาน) · `เฉพาะแผนกของตน` (เห็นงานที่สมาชิกในแผนกเกี่ยวข้อง
  และมอบหมาย/จัดการได้เฉพาะคนในแผนก — ผู้ใช้ต้องระบุแผนก) · `เฉพาะงานของตน`
- **สิทธิ์** (ติ๊กเลือก): ดูแดชบอร์ดภาพรวม, สร้างงาน, มอบหมายงานให้ผู้อื่น, แก้ไขงานของผู้อื่น, ลบงานของผู้อื่น,
  ตอบกลับรายงาน/ปิดปัญหา, รับแจ้งเตือนในฐานะหัวหน้า, รับมอบหมายงานได้
- เพิ่มบทบาทใหม่ได้ (เช่น “รองหัวหน้าแผนก”) โดยเลือกขอบเขตและคัดลอกสิทธิ์จากบทบาทเดิม · บทบาทพื้นฐาน 4 บทบาทลบไม่ได้
  แต่ปรับชื่อ ขอบเขต และสิทธิ์ได้ · ลบบทบาทที่เพิ่มเองได้เมื่อไม่มีผู้ใช้
- บทบาท **ผู้ดูแลระบบ** ถูกล็อก (เห็นทุกงาน + เมนูผู้ดูแลระบบ) เพื่อป้องกันการตัดสิทธิ์ตนเองโดยไม่ตั้งใจ
- ผู้สร้างงานแก้ไขและลบงานที่ตนสร้างได้เสมอ

**ค่าเริ่มต้น** (ตาราง permissions ใน `taskapp/permissions.py`):

| ความสามารถ | ผู้ดูแลระบบ | หัวหน้าหน่วยงาน | หัวหน้าแผนก | พนักงาน |
|---|:-:|:-:|:-:|:-:|
| ดู Task | ทุกงาน | ทุกงาน | งานที่สมาชิกในแผนกเกี่ยวข้อง (รับผิดชอบ/งานย่อย/สร้าง) + งานของตน | เฉพาะงานที่ได้รับมอบหมายหรือตนสร้าง |
| แดชบอร์ดภาพรวม + ภาระงาน | ทั้งหน่วยงาน | ทั้งหน่วยงาน | เฉพาะแผนกตน | แดชบอร์ดส่วนตัว |
| สร้าง Task | ✔ | ✔ | ✔ | ✔ (มอบหมายให้ตนเองอัตโนมัติ) |
| มอบหมายผู้รับผิดชอบหลายคน | ทุกคน (พนักงาน + หัวหน้าแผนก) | ทุกคน | เฉพาะสมาชิกในแผนก | |

| แก้ไข / ลบ / เปลี่ยนสถานะ Task ของผู้อื่น | ทุกงาน | ทุกงาน | งานที่ตนหรือสมาชิกในแผนกสร้าง | เฉพาะงานที่ตนสร้าง |

- **หัวหน้าแผนก** ต้องระบุหน่วยงานและแผนกที่ดูแล งานที่หัวหน้าหน่วยงานสร้างจะแก้ไขได้เฉพาะหัวหน้าหน่วยงาน
  แต่หัวหน้าแผนก **มอบหมายต่อให้ลูกน้องในแผนกได้** จากการ์ด “มอบหมายงานให้ลูกน้อง” ในหน้างาน (เพิ่ม/นำออกได้เฉพาะคนในแผนก)
  รวมทั้งดู ตอบกลับรายงาน และปิดสถานะปัญหาได้ เมื่อหัวหน้าแผนกแก้ไขผู้รับผิดชอบ ผู้รับผิดชอบจากแผนกอื่นจะคงไว้ตามเดิม
  หัวหน้าแผนกเองก็รับมอบหมายงานจากหัวหน้าหน่วยงานได้เช่นเดียวกับพนักงาน
- ผู้ดูแลระบบไม่สามารถลดสิทธิ์/ปิดการใช้งานบัญชีของตนเอง และระบบต้องมีผู้ดูแลระบบที่ใช้งานอยู่อย่างน้อย 1 คนเสมอ
- ผู้ใช้แต่ละคนสังกัดได้ 1 หน่วยงานและ 1 แผนก (ไม่บังคับ) โดยแผนกต้องอยู่ในหน่วยงานที่เลือก
  ลบหน่วยงาน/แผนกได้เฉพาะเมื่อไม่มีผู้ใช้สังกัดอยู่ (ลบหน่วยงานจะลบแผนกในหน่วยงานนั้นด้วย)
- การแจ้งเตือนปัญหา/อุปสรรคส่งถึง “หัวหน้าหน่วยงาน” และ “หัวหน้าแผนก” ของผู้รายงาน (ผู้ดูแลระบบไม่ได้รับ เพราะไม่ได้อยู่ในสายงานประจำวัน)

## ปีการศึกษา

- ปีการศึกษา พ.ศ. X = **1 สิงหาคม X ถึง 31 กรกฎาคม X+1** เช่น ปีการศึกษา 2569 = 1 ส.ค. 2569 – 31 ก.ค. 2570
  (ผู้ดูแลระบบกรอกแค่ปี ระบบเติมวันที่ให้ และปรับแก้วันได้ โดยห้ามช่วงวันที่ซ้อนทับกับปีอื่น)
- งานแต่ละงานสังกัด 1 ปีการศึกษา: เลือกเองในฟอร์ม หรือ “อัตโนมัติ” ตามวันเริ่มต้นงาน (ถ้าไม่มี ใช้วันครบกำหนด / วันนี้)
  หากวันที่อยู่นอกทุกปีที่มี ระบบจะสร้างปีการศึกษานั้นให้อัตโนมัติ
- แดชบอร์ดและรายการงานแสดง **ปีการศึกษาปัจจุบัน** เป็นค่าเริ่มต้น เลือกปีอื่นหรือ “ทุกปีการศึกษา” ได้จากตัวกรอง
- ผู้ดูแลระบบกำหนด “ปีปัจจุบัน” ได้เอง (ถ้าไม่กำหนด ใช้ปีที่ครอบคลุมวันนี้) และลบได้เฉพาะปีที่ไม่มีงานและไม่ใช่ปีปัจจุบัน

## กฎทางธุรกิจ

- **น้ำหนักงานย่อยเป็นเปอร์เซ็นต์ของงานหลัก** (0.1–100, ทศนิยม 1 ตำแหน่ง) และน้ำหนักของงานย่อยทั้งหมดในงานเดียวกัน
  **รวมกันต้องไม่เกิน 100%** — ระบบตรวจทั้งตอนเพิ่มและแก้ไข ถ้าเว้นว่าง จะใช้เปอร์เซ็นต์ที่เหลือทั้งหมด
  เมื่อรวมครบ 100% แล้ว ต้องลดน้ำหนักงานย่อยอื่นก่อนจึงจะเพิ่มงานย่อยใหม่ได้
- **ความคืบหน้า Task** = Σ(ความคืบหน้างานย่อย × น้ำหนัก%) / Σ(น้ำหนัก%) — คำนวณใน SQL ทุกครั้งที่แสดงผล
  (ถ้าน้ำหนักรวมยังไม่ครบ 100% จะคิดตามสัดส่วนของน้ำหนักที่กำหนดไว้ และหน้างานจะแสดงส่วนที่ยังไม่ได้กำหนด)
  ถ้าไม่มีงานย่อย จะใช้ค่าที่หัวหน้าหรือผู้รับผิดชอบกรอกเอง
- **สถานะงานย่อยกับเปอร์เซ็นต์สอดคล้องกันอัตโนมัติ:** เลือก “เสร็จสิ้น” → 100%, กรอก 100% → “เสร็จสิ้น”, กรอก > 0% ขณะ “ยังไม่เริ่ม” → “กำลังดำเนินการ”
- Task ที่ “ยังไม่เริ่ม” จะเปลี่ยนเป็น “กำลังดำเนินการ” อัตโนมัติเมื่อมีความคืบหน้า > 0 (การปิดงานเป็น “เสร็จสิ้น” ให้หัวหน้าเป็นผู้ยืนยัน)
- เมื่อมอบหมายงานย่อยให้พนักงานที่ยังไม่อยู่ใน Task ระบบจะเพิ่มเป็นผู้รับผิดชอบ Task ให้อัตโนมัติ
- **เลยกำหนด** = วันครบกำหนด < วันนี้ และสถานะไม่ใช่ “เสร็จสิ้น” หรือ “ระงับ”
- รายงานที่มีการกรอก “ปัญหา” หรือ “อุปสรรค” จะถูกนับเป็น *ปัญหารอแก้ไข* จนกว่าหัวหน้าจะกด “แก้ไขแล้ว”
- ตัวกรองช่วงวันที่: แสดง Task ที่ช่วง [วันเริ่มต้น, วันครบกำหนด] คาบเกี่ยวกับช่วงที่เลือก

## การแจ้งเตือน (ในระบบ — ไอคอนกระดิ่ง)

| เหตุการณ์ | ผู้รับ |
|---|---|
| ได้รับมอบหมาย Task / งานย่อยใหม่ | พนักงานที่ได้รับมอบหมาย |
| Task/งานย่อยใกล้ครบกำหนด (ค่าเริ่มต้น 3 วัน ปรับได้ในหน้าตั้งค่าระบบ) | ผู้รับผิดชอบ |
| Task/งานย่อยเลยกำหนด | ผู้รับผิดชอบ + หัวหน้าผู้สร้างงาน |
| พนักงานรายงานปัญหา/อุปสรรค | หัวหน้าหน่วยงานทุกคน + หัวหน้าแผนกของผู้รายงาน |
| พนักงาน/หัวหน้าแผนกเพิ่มงานเอง | หัวหน้าหน่วยงานทุกคน + หัวหน้าแผนกของผู้สร้าง |
| หัวหน้าตอบกลับ / ปิดปัญหา | พนักงานผู้รายงาน |

การแจ้งเตือนเรื่องกำหนดส่งจะถูกตรวจสอบอัตโนมัติขณะมีผู้ใช้งานระบบ (ทุก 5 นาที) และมี `dedupe_key` ป้องกันการแจ้งซ้ำ
(หากเลื่อนวันครบกำหนด จะแจ้งเตือนใหม่ตามวันใหม่)

## ความปลอดภัย

- รหัสผ่านเก็บแบบ hash (Werkzeug), ทุกฟอร์ม POST มี CSRF token
- ตรวจสิทธิ์ทุก route ฝั่งเซิร์ฟเวอร์ (รวมถึงการดาวน์โหลดไฟล์แนบ)
- ไฟล์แนบจำกัดนามสกุล (pdf, office, รูปภาพ, txt/csv, zip/rar) และขนาดรวมไม่เกิน 20 MB ต่อครั้ง
